# Faculty Evaluation Database Data Dictionary

This document describes the schema in `faculty_evaluation_db (1).sql` and the
relationships defined by its foreign keys. It reflects the SQL dump in this
repository, not necessarily a live database that may have since changed.

See the [entity relationship diagram](./ERD.md) for a visual overview of the
tables and foreign keys.

## Conventions

- `PK`: primary key; `FK`: foreign key; `UQ`: unique constraint/index.
- `NULL` means the column accepts a missing value. `NOT NULL` means a value is
  required.
- `AUTO_INCREMENT` columns are generated by MariaDB.
- `created_at` and `updated_at` record row creation and last update where
  present. `updated_at` is updated automatically by MariaDB.
- Password columns are intended for password hashes, not plaintext passwords.

## Relationship overview

| Parent | Child | Relationship |
|---|---|---|
| `add_programs` | `add_classes` | One program can have many classes. |
| `add_programs` | `add_subjects` | One program can have many subjects. |
| `evaluation_periods` | `add_classes` | A period can be associated with many classes; a class may have no period. |
| `evaluation_periods` | `evaluations` | A period can contain many evaluations; an evaluation may have no period. |
| `evaluation_periods` | `evaluation_settings` | A period may be selected as the active period. |
| `add_categories` | `add_questions` | One category has many questions; deleting a category cascades to its questions. |
| `add_classes`, `add_subjects`, `add_faculties` | `class_subjects` | Class-subject assignment and assigned faculty. |
| `add_faculties`, `add_subjects` | `faculty_subjects` | Faculty-to-subject association. |
| `add_students`, `add_subjects` | `student_subjects` | Student-to-subject association. |
| `add_students`, `add_subjects`, `add_classes` | `student_subject_classes` | Student enrollment in a subject and class. |
| `add_students`, `add_faculties`, `add_subjects`, `add_classes`, `evaluation_periods` | `evaluations` | Evaluation context. |
| `evaluations`, `add_questions` | `evaluation_answers` | Question ratings belonging to an evaluation. |
| `add_faculties` | `faculty_login` | Faculty login/profile; deleting the profile deletes its login row. |
| `add_students` | `student_login` | Login username matches the student's student number. |
| `add_faculties` | `faculty_uploaded_reports` | Reports associated with a faculty profile. |

## Import and data notes

- This dictionary describes the SQL structure and constraints. It does not
  confirm the current contents of a live database.
- The accompanying dump includes an administrator seed row but does not
  include general student, faculty, subject, class, or evaluation data.
- `evaluations.subject_id` and `evaluations.class_id` are `NOT NULL` with a
  default of `0`, while foreign keys require matching parent IDs. Application
  records must therefore use valid subject and class IDs (not `0`) when these
  constraints are applied.
- The schema allows deleting categories to delete questions and deleting an
  evaluation to delete its answers. Other evaluation and report relationships
  restrict deleting their referenced parent rows.
